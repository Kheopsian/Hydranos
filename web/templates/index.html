Categories

For a category things graduate INTO. A torrent that arrives here is deleted once its tracker's minimum seed time is paid. Leave it off and this is a library: torrents that graduate here stay for good.
Race only. What happens under disk pressure is decided by the tracker, not here: a torrent that has served its minimum seed time is deleted, one that still owes seeding moves to this category to finish paying it, and is deleted there once it has. Leave this empty and a torrent that still owes seeding can only wait.
Every strategy except "all" places the torrent on ONE agent. Space and load are measured at this category's own path on each agent, not on the agent as a whole.
An agent with less than this left at the category path gets no new torrents, whatever the strategy, "all" included. 0 or blank = no reserve.
Which agents host new torrents in this category. Blank per-agent path = the flat save path above. Only "local" until remote agents are configured.

Nodes

A node is a whole Hydranos. This one runs the engines listed below; the others are separate instances reached over their own API. An engine is a session inside a node, and a node can run as many as it has tunnels to leave by.

Run this on the machine that is to become a node. It installs Hydranos, gives it its own key, and registers itself here. This Hydranos never opens a session on it and never holds a credential for it. The token works once, for 30 minutes.

Duplicate data

                

                

                    

                        

                            On adding a torrent we already hold
                            Sets [dedup] enabled. Hardlinks the files we already hold under the new torrent's names, so it seeds at once without downloading them again. On by default: a link costs a directory entry, downloading the same data again costs the bandwidth and the disk.
